Summary:
Built the Settings page with full habit management. The server page fetches all habits
(including archived) via getHabits(true), splits them by active flag, and renders the
HabitSettingsList client component. Each habit row shows the name, a frequency badge
(Daily / Weekdays / Custom), an Edit button opening a pre-filled dialog, and an
Archive/Reactivate toggle button. All state mutations use useTransition for pending
states. The EditHabitDialog reuses the exact same segmented frequency picker pattern
from AddHabitDialog. The nav link to /settings was already present in app-nav.tsx.

Screenshots:

  separate from active habits, Archive button replaced with emerald Reactivate.
