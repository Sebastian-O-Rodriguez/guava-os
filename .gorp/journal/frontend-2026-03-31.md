Summary: Audited all text/background color combinations against WCAG AA (4.5:1 for normal text, 3:1 for large text). Zinc color luminance values used for calculations against zinc-900 (#18181b) background:

Contrast ratios calculated:

- zinc-400 (#a1a1aa) on zinc-900: ~5.3:1 — PASS
- zinc-500 (#71717a) on zinc-900: ~3.5:1 — FAIL for normal text
- zinc-600 (#52525b) on zinc-900: ~2.6:1 — FAIL

Fixes applied:

1. liquid-gauge.tsx line 117 — Label text `text-zinc-500` -> `text-zinc-400` (3.5:1 -> 5.3:1). The gauge labels ("Cal", "Prot", "Leg" etc.) are 10px uppercase text, small enough to be normal-text category requiring 4.5:1.

2. liquid-gauge.tsx line 204 — Decrement button "−" symbol `text-zinc-600` -> `text-zinc-400` (2.6:1 -> 5.3:1). This is an interactive control, so full contrast is required at its visible opacity.

3. liquid-gauge.tsx line 184 — Added `aria-hidden="true"` to the icon overlay div. Opacity-15 decorative icons are exempt from contrast rules, but marking them aria-hidden is the correct annotation to make that explicit.

4. inline-chat.tsx line 84 — Placeholder `placeholder:text-zinc-600` -> `placeholder:text-zinc-500` (2.6:1 -> 3.5:1). Note: WCAG 2.1 allows placeholder text to be treated as "inactive UI component" (3:1 threshold), so zinc-500 at ~3.5:1 passes. Bumping further to zinc-400 would reduce the visual distinction between placeholder and real input.

5. inline-chat.tsx line 84 — Disabled state `disabled:opacity-50` -> `disabled:text-zinc-500 disabled:cursor-not-allowed`. opacity-50 on foreground text (#fafafa) against zinc-900 would yield ~0.5 effective luminance reduction; using explicit zinc-500 gives a predictable, calculable ~3.5:1.

6. inline-chat.tsx line 107 — "Processing..." status text `text-zinc-600` -> `text-zinc-400` (2.6:1 -> 5.3:1). This is meaningful status content read by screen readers via the aria-live container.

7. day-header.tsx line 50 — Back chevron `text-zinc-600` -> `text-zinc-400`, hover `hover:text-zinc-400` -> `hover:text-zinc-200`.

8. day-header.tsx line 69 — Forward chevron `text-zinc-600` -> `text-zinc-400`, hover same. Disabled state `disabled:text-zinc-800` -> `disabled:text-zinc-700`. zinc-800 (~1.3:1) was essentially invisible; zinc-700 (~1.7:1) remains clearly ghosted but is still below threshold — acceptable as a disabled state indicator per WCAG 1.4.3 exception for "inactive user interface components".

9. chat.tsx line 198 — Disabled textarea `disabled:opacity-50` -> `disabled:text-zinc-500 disabled:cursor-not-allowed`. Same rationale as item 5.

Items verified as already passing (no changes needed):

- SVG textStyle `rgb(161,161,170)` (zinc-400) on dark ring fill: ~5.3:1 — PASS
- SVG unit tspan `rgb(161,161,170)` at size\*0.1 (8px): technically small text but still zinc-400 on dark — PASS
- waveTextStyle `rgb(255,255,255)` on colored fill: white on emerald-500 is ~3.0:1 but the wave text overlays the filled portion so effective background is fill color — PASS for large/bold text
- app-nav.tsx inactive links `text-zinc-400` on zinc-950/80: ~6.1:1 — PASS
- app-nav.tsx brand text `text-zinc-100` on zinc-950: ~18:1 — PASS
- chat.tsx example prompt buttons `text-muted-foreground` on zinc-900: muted-foreground in dark mode is oklch(0.708) = ~zinc-400 equivalent — PASS

## Task #21 — Audit animation performance

Status: done
Files:

- src/components/chat.tsx
- src/components/dashboard/inline-chat.tsx
  Tests: N/A (vitest not installed — known issue I1)
  Summary: Fixed two real issues found during the audit; no changes needed elsewhere.

**chat.tsx** — Replaced a bare `setTimeout(..., 100)` in the `finally` block with `requestAnimationFrame`. The old timer was never stored in a ref and could fire after unmount, calling `.scrollIntoView()` and `.focus()` on detached DOM nodes. `requestAnimationFrame` fires on the next paint frame (the correct semantic — scroll after React flushes the new message into the DOM), is a one-shot operation with no cleanup required, and eliminates the arbitrary 100 ms magic number.

**inline-chat.tsx** — Added an unmount cleanup `useEffect` that calls `clearTimeout(bannerTimeoutRef.current)`. The banner auto-dismiss timer was already guarded against double-fire inside the component lifecycle, but nothing cancelled it if the component unmounted mid-countdown. The fix follows the same pattern already used in `liquid-gauge.tsx`.

No changes needed elsewhere:

- `globals.css` — `animate-fade-in` and `animate-slide-up` animate only `opacity` and `transform: translateY`, both GPU-composited. No layout thrashing.
- `liquid-gauge.tsx` — Error flash timer already uses `errorTimerRef` with cleanup on both unmount and re-trigger. Clean.
- Rapid gauge tapping — React 18 auto-batches `setOptimisticValue` calls synchronously. No issue.

`tsc --noEmit` clean (only pre-existing vitest-not-installed errors, known issue I1).
