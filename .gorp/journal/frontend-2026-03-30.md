## Task 4 — Error Handling for Server Action Failures in Dashboard Cards

Status: done
Files:

- src/components/dashboard/liquid-gauge.tsx
- src/components/dashboard/nutrition-card.tsx
- src/components/dashboard/fitness-card.tsx

Tests: n/a (no test infrastructure)
Summary:

Dashboard cards previously called quick-log server actions and discarded the ActionResult, leaving failures completely silent and the optimistic state permanently wrong.

Changes:

liquid-gauge.tsx — Added `GaugeActionCallbacks` exported type with a `rollback: () => void` member. Added `errorFlash` state + `errorTimerRef`. `triggerErrorFlash(snapshot)` reverts `optimisticValue` to the snapshot and activates a `ring-2 ring-red-500/80` ring around the gauge circle for 1200ms. `handleClick` captures a snapshot before the optimistic update and passes `{ rollback: () => triggerErrorFlash(snapshot) }` as the second argument to `onIncrement`. Same pattern for the decrement handler. A sr-only `aria-live="assertive"` span announces "Failed to save [label]" during the flash. The `readOnly` prop (also added) disables all interactions and dims the gauge on past-day views.

nutrition-card.tsx — `handleIncrement`/`handleDecrement` now destructure `{ rollback }` from `GaugeActionCallbacks` and call `rollback()` when `result.success` is false. Added `readOnly?: boolean` prop; passes `undefined` to gauge action handlers when true.

fitness-card.tsx — Same pattern applied to all four action handlers (gym increment, gym decrement, run increment, run decrement). Added `readOnly?: boolean` prop.

Also fixed: `page.tsx` was already passing `readOnly={!isToday}` to both cards but the prop was missing from both card type definitions — resolved as part of this work.

Visual result: On server action failure, the affected gauge snaps back to its pre-tap value and shows a red ring for ~1.2 seconds. No toast library added.

## Task #2 — Fix right-click decrement UX

Status: done
Files:

- src/components/dashboard/liquid-gauge.tsx

Tests: 0 (no test infrastructure, known issue I1)

Summary:
Replaced the `onContextMenu` right-click decrement with a visible [-] button rendered below each gauge. The button appears on hover on pointer devices and is always visible on touch/coarse-pointer devices via `[@media(pointer:coarse)]:opacity-100`. `e.stopPropagation()` prevents the button click from bubbling up to the gauge and triggering an increment. The gauge's `onClick` (increment) was moved from the outer wrapper div to the inner gauge div only, so clicks on the button are cleanly isolated. The outer wrapper gained `group` to drive the hover-reveal.

Key decisions:

- `canDecrement` is false when value is 0 or readOnly is true; button renders but is invisible and pointer-events-none when disabled, avoiding layout shift
- The button renders only when `onDecrement != null`, so gauges without a decrement handler show nothing below
- Kept `GaugeActionCallbacks` with `cbs` required to stay consistent with how nutrition-card and fitness-card destructure `{ rollback }` from it
- `handleContextMenu` removed entirely; native right-click menu is restored

Screenshots:

- Pointer device: a small dim "−" pill with zinc-800 border appears under each gauge when the card is hovered; disappears when cursor leaves. Brightens on button hover.
- Touch device: same pill is always visible below each gauge, giving users a persistent decrement affordance.
