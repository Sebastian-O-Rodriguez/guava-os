## Task S6-W2 — Chat Classifier + Deterministic Executor

Status: done

Files:

- `src/lib/chat-scenarios.ts` — created (Zod schemas for classifier output + per-scenario params)
- `src/lib/chat-classifier.ts` — created (single LLM call returning validated ClassifierOutput)
- `src/lib/chat-executor.ts` — created (deterministic scenario dispatcher + template responses)
- `src/lib/chat-prompt.ts` — replaced (old SYSTEM_PROMPT → CLASSIFIER_PROMPT for JSON-only classification)
- `src/lib/chat-tools.ts` — emptied (superseded; kept as empty module)
- `src/app/api/chat/route.ts` — rewritten (multi-turn tool-use loop replaced with classify → execute)

Tests: 0 (vitest not installed per known issue I1)

Summary:
Refactored the chat pipeline from a multi-turn LLM tool-calling loop to a two-step
classifier + deterministic executor pattern. The LLM is now called exactly once per
user message and must return a JSON object with { scenario, params }. All business
logic (DB writes, progress queries, category resolution, template response construction)
runs deterministically in the executor without any further LLM involvement.

Seven supported scenarios: log_nutrition, log_gym, log_run, set_goal, add_category,
query_progress, unknown. The classifier prompt includes macro estimation instructions
for nutrition logging so the LLM can estimate calories/protein/fat/carbs from natural
food descriptions without an external API.

The executor auto-creates the canonical category (Gym, Nutrition, Running) if it does
not yet exist via findOrCreateCategoryId. For goal-setting it resolves a category by
type match first, then fuzzy name match via resolveCategoryId.

The chat.tsx frontend component continues to work: data.message is consumed as before;
the old toolResults cards simply never render since the new route no longer returns
that field.

pnpm tsc --noEmit: zero errors in any of the new/modified files. Pre-existing errors
in completions.ts, habits.ts, and UI components are unchanged from before this task.
