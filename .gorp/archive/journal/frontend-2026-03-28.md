## Task #20 — Cross-browser testing fixes

Status: done
Files:

- src/components/chat.tsx (removed fieldSizing style prop)
- src/components/app-nav.tsx (added data-nav-root attribute)
- src/app/globals.css (added Firefox backdrop-blur @supports fallback)
  Tests: tsc --noEmit clean (0 errors)
  Summary:
  Three browser compatibility issues addressed:

1. fieldSizing: "content" removed from chat.tsx textarea. This CSS property is
   experimental (Chrome 123+ only, no Firefox/Safari support). The style was cast via
   "as unknown as React.CSSProperties" to suppress the TS error — a sign it should not
   be there. The manual height-resize logic in handleInput already provides a
   cross-browser equivalent (scrollHeight calculation). Line removed, cast removed.

2. Firefox backdrop-blur fallback added to globals.css. Firefox historically requires
   the layout.css.backdrop-filter.enabled flag and has had rendering inconsistencies
   with backdrop-filter. A @supports not (backdrop-filter: blur(1px)) block now sets
   background: rgb(9,9,11) on [data-nav-root], providing a solid opaque background
   so the nav remains legible in Firefox without blur. The data-nav-root attribute was
   added to the <nav> element in app-nav.tsx to serve as the CSS hook.

3. oklch colors in globals.css — verified. All oklch values are in CSS custom properties
   consumed via var() references. Tailwind v4's build output converts utility classes to
   computed values at build time, so oklch is not a direct compatibility risk for
   supported browsers (all evergreen browsers since 2023 support oklch). No action needed.

4. SVG clipPath in liquid-gauge.tsx — verified. The clipPath is generated internally by
   react-liquid-gauge and rendered server-side via dynamic() with ssr: false. We have no
   control over the SVG internals. The ssr: false loading skeleton (rounded-full
   bg-zinc-800/80 div) is the only Safari-safe fallback we own, and it is already in place.
